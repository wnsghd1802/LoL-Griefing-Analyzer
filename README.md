# LoL 트롤링 판독기 v6.0 — BR-B / AI 과제 13단계

**공개 페이지:** https://lol-griefing-analyzer.vercel.app/  
**GitHub 소스:** https://github.com/wnsghd1802/LoL-Griefing-Analyzer  
**연계 연구(과제 10):** 「팀 기반 온라인 게임에서 비협조적 행동의 발생 요인과 제재 판단의 한계에 관한 연구」

## 현재 사용자 흐름
1. 필요하면 라이엇 ID(게임 이름#태그)를 입력하고 OP.GG 전적 페이지를 엽니다.
2. 경기 영상을 **한 번 선택하면 자동으로 OCR 분석**이 시작됩니다. 별도 메뉴, 채팅 수동 입력, JSON 파일은 기본 사용 흐름에서 필요하지 않습니다.
3. 채팅 로그·의심 표현·영상 시간·진행률을 **한 페이지**에서 확인합니다. 채팅 시간을 누르면 영상의 해당 시점으로 이동합니다.
4. 전적 검색 사이트의 **스코어보드 스크린샷**을 선택하면 KDA·CS 후보를 OCR로 추출합니다. 다수 선수 중 닉네임과 연결할 수 없으면 임의로 특정하지 않습니다.
5. 자동 결과를 TXT로 저장합니다. '예시 결과 보기'는 사용자 파일 없이 작동하는 **가상 데이터 시연**입니다.

## 동료 의견과 반영
> 페이지의 의도는 좋으나 페이지가 너무 번잡스럽다 좀 더 한 눈에 보였으면 좋겠다.

메뉴 6개와 여러 수동 입력을 전면에 두던 구조를 없애고, 영상 선택 → 자동 분석 → 채팅 로그/의심 시각 → 결과 저장의 단일 화면으로 변경했습니다. 전적 검색과 스크린샷 OCR은 선택 기능입니다. 페이지 하단에 동료의 한마디와 반영 내용을 공개합니다.

## 기술적 한계 — 완료라고 주장하면 안 되는 부분
- OCR은 Tesseract.js를 사용하며 최초 실행 때 한국어·영어 모델을 내려받습니다. 분석 대상 영상과 이미지는 서버로 업로드하지 않습니다.
- 동영상에 채팅창이 보이지 않거나 순간적으로 나타났다 사라지면 누락할 수 있습니다. 다른 HUD 글자를 채팅으로 오인할 수도 있습니다.
- 닉네임 입력은 **OP.GG 검색 바로가기**이며 Riot API를 이용한 전적 자동 조회 기능은 아닙니다. 전적 스크린샷은 OCR 후보를 표시하므로 원본과 대조해야 합니다.
- **실제 LoL 녹화 영상에 대한 인식률/재현율은 아직 실측되지 않았습니다.** 합성 영상/샘플 테스트 결과를 실제 경기 성능이라고 말하지 않습니다.
- KDA·CS나 욕설 한 문장만으로 고의적 방해·제재 여부를 단정하지 않습니다. 연구의 장면 발견 → 분류 → 맥락 점검 → 반례 확인 → 최종 검토 순서를 참고합니다.

## 바로 시작하기

1. ZIP을 압축 해제하고 `index.html`을 Chrome 또는 Edge에서 엽니다. 계정·비밀번호·API 키는 필요 없습니다.
2. **예시로 먼저 해보기**를 누릅니다. 가상 타임라인에서 **사망 집중 / 위치 변화 감소 / 정글러의 일반 미니언 획득 집중** 후보가 나오는지 확인합니다.
3. **영상 보기 → 영상 파일 선택**에서 영상을 고르고 **영상 분석 시작**을 누르면 채팅 OCR이 시작됩니다. 검사 화면 간격은 기본 2초이며 변경할 수 있습니다. 긴 영상의 검사는 오래 걸릴 수 있습니다. 글자 미리보기에 실제 인식된 문구가 표시됩니다.
4. Riot Match-V5 **타임라인 JSON**을 가지고 있다면 **자동 후보 찾기 → Riot 타임라인 JSON 선택**으로 불러옵니다. 정글러의 `participantId`를 직접 확인한 경우에만 지정합니다. (지정하지 않으면 CS 방해 후보는 추출하지 않습니다.)
5. 각 후보에서 **해당 시점 이동 → 정상적인 다른 이유 검토 → 검토 상태 선택 → 후보 목록 저장**을 진행합니다.

합성 OCR 확인 영상은 `sample_data/ocr_synthetic_open.mp4`입니다. 실제 사람·경기 자료가 아닙니다. 영상 없이도 `예시로 먼저 해보기`로 앱을 체험할 수 있습니다. `채팅 확인` 탭에서 예시 문구 탐지, `CS 변화` 탭에서 가상 CS 그래프를 시험할 수 있습니다.

## 실제 자동화 범위

| 기능 | 상태 | 주의 |
|---|---|---|
| 영상 채팅 OCR 샘플링 | 구현 · 실제 한국어 OCR 성능 미검증 | 인터넷에서 Tesseract.js 한국어/영어 모델 다운로드 필요. 채팅이 보이는 순간을 샘플링하지 못하면 놓칩니다. |
| OCR 문구의 규칙 탐색 | 구현 · 간단한 규칙 | '오픈'을 포함해도 실제 포기 판정은 불가능. 인용, OCR 오인식 가능 |
| Riot 타임라인의 사망 집중 후보 | 구현 | 반복 사망은 고의적 사망과 다름 |
| Riot 타임라인의 위치 변화 감소 | 구현 | 사망/부활/기지 체류/분 단위 프레임 문제로 오탐 가능 |
| 정글러 라인 CS 획득 집중 | 구현 · 사용자가 정글러 ID 선택 | `minionsKilled` 변화량이며 특정 라이너의 CS 탈취를 증명하지 못함 |
| 증거 관리, 정상적 반례·판단 보류, JSON 내보내기 | 구현 | 개인정보 내보내기 전에 검토 필요 |
| 넥서스 방어 이탈, 고의적 죽음, 의도적 CS 탈취 자동 판정 | **미구현** | 맥락을 포함한 영상/리플레이 인식 및 검증 필요 |
| 유튜브 URL만으로 영상 분석 | **미지원** | 공개 영상 주소는 근거 출처로 기록만 가능 |
| 논문의 학습된 토큰 점수 분류기 재현 | **미구현** | 현재 앱은 간단한 OCR/금칙어 및 패턴 기반 탐색 |

**영상 크기:** 명시적 업로드 제한은 없습니다. 영상은 브라우저의 Blob URL로 로컬 재생하고 프레임만 추출합니다. **5GB·10GB 이상 파일의 정상 작동을 검증하지 않았습니다.** 브라우저 코덱 지원, CPU, 메모리, 영상 손상 여부가 영향을 줍니다. 특히 HEVC 녹화 영상은 브라우저에서 재생되지 않을 수 있습니다.

**전체 영상 OCR:** 시작·종료 시각을 지정하지 않으면 영상의 끝까지 읽습니다. OCR 요청 횟수가 많아지면 오래 걸리므로 한 번에 **최대 1,800개 프레임**으로 제한하며, 중지 버튼을 지원합니다. 짧게 나타난 채팅은 누락될 수 있습니다. 대용량 영상의 OCR 처리 속도와 정확도는 사용자의 PC에서 직접 시험해야 합니다.

**Riot 데이터:** Match-V5의 `info.frames`를 가진 `timeline.json`을 사용합니다. `match.json`을 잘못 넣거나 타임라인이 없으면 오류 메시지를 표시합니다. `participantId`가 어느 역할인지 파일 자체로 확인되지 않을 수 있으므로 수동으로 지정해야 합니다. 영상 재생 시간과 게임 시간은 서로 다를 수 있습니다.

## 개인정보·오탐

- 영상은 현재 앱 서버로 업로드하지 않습니다. OCR 라이브러리 모델은 외부 CDN에서 다운로드됩니다. 원본 파일을 통째로 전달하지 않도록 구현했습니다.
- OCR을 통해 플레이어 이름, 채팅이 읽힐 수 있습니다. 외부 공유 전 익명화하세요.
- 탐색 결과는 `검토 필요 / 판단 불가 / 정상 설명 가능 / 추가 근거 확인`으로 관리합니다. 고의성 확정·계정 제재는 제공하지 않습니다.
- 연구 기준인 **관찰된 사실 → 반복성 → 경기 맥락 → 정상적인 대안 → 근거 종합**을 적용합니다.

Vercel 측 배포 상태 READY 및 URL HTTP 200 응답은 별도로 확인했습니다. **합성 MP4 영상에서 한국어 ‘오픈함’ OCR 탐지 성공을 확인했으나, 실제 LoL 게임 영상의 인식률과 10GB 대용량 파일은 아직 실증 테스트하지 않았습니다.**

## 선택 기능 — 10GB 영상용 Python 로컬 OCR

Chrome에서 HEVC 코덱이 재생되지 않거나 아주 긴 영상을 분석해야 한다면, **같은 ZIP에 포함된** `offline_scan.py`로 FFmpeg를 사용하여 파일을 직접 읽을 수 있습니다. 영상 전체를 메모리에 올리지 않고 선택 시점의 프레임만 추출합니다.

사전 준비: Python 3.9+, FFmpeg (`ffmpeg`, `ffprobe`), Tesseract OCR (`tesseract`) 및 **한국어(`kor`)·영어(`eng`) 언어 데이터**를 PATH에서 사용할 수 있어야 합니다. Windows에서는 해당 프로그램을 별도로 설치해야 합니다. 이 ZIP에는 실행 파일이나 언어 모델을 동봉하지 않았습니다.

```bash
python offline_scan.py "D:\Videos\game.mp4" --step 8 --out result.json
```

실행 후 앱의 **자동 후보 찾기 → 오프라인 분석 결과 불러오기**에서 `result.json`을 선택하면 결과를 영상 시각·근거 후보 목록에 추가할 수 있습니다. 오프라인 스캐너는 채팅 영역의 OCR 문구만 검사하며 고의적 방해 동작을 판정하지 않습니다. 브라우저 자동 탐색과 별개의 선택 기능입니다.


## v5 변경 사항 (2026-11-04)

- 영상 파일을 열면 **영상 분석 시작** 버튼이 활성화됩니다. 채팅 자동 읽기와 화면 변화 분석을 선택할 수 있습니다.
- **화면 변화 분석**은 로컬 비디오에서 10/20/30초 간격으로 프레임을 읽어 흑백 전환과 정지 화면을 표시합니다. 화면 전환과 정지 상태를 찾는 알고리즘이며, AFK·고의적 사망·트롤링 여부를 판단하지 못합니다.
- 발견된 시각을 클릭하면 해당 영상 구간으로 이동합니다. **이 장면 자세히 확인**을 선택하면 발생 시간과 발견 내용이 검토 화면에 자동으로 입력됩니다.

## v5.4 채팅 OCR 감지 개선 (2026-11-05)
- **재생 중 채팅 감시(기본 켜짐)**: 영상 파일을 열고 재생하면 OCR이 가능한 속도로 화면을 반복 확인하고 의심 문구를 찾으면 결과 목록에 즉시 추가합니다. 처리 중 다음 프레임을 무조건 큐에 넣지 않습니다.
- **영상 전체 분석 기본 2초 간격**(1초/4초/8초 선택): 기본 4초에서 간격을 줄이고 발견 즉시 표시하게 변경했습니다. 세밀한 검사일수록 시간이 오래 걸립니다.
- **LoL 채팅창 우선 분석**: HUD까지 포함하던 하단 영역 대신 왼쪽 채팅 중심으로 기본 범위를 조정했습니다. 왼쪽 넓게/전체 화면 옵션도 제공합니다.
- **실제 OCR 입력 화면 확인**: ‘실제 읽힌 채팅 글자 확인’에 잘라낸 이미지와 인식 텍스트를 표시하여 채팅이 잘렸는지 판별할 수 있습니다.
- **OCR 대비 보정 재시도**: 글자를 읽지 못하는 상황에서 흑백 고대비 변환으로 다시 읽습니다.
- **한국어 표현 보강**: 축약 욕설과 띄어쓰기 변형 규칙을 추가했습니다. 이상 문구는 실제 트롤링 확정이 아닙니다.
- **제한**: 라이엇 클라이언트의 실시간 채팅은 별도로 수집하지 않습니다. 사용자가 불러온 녹화 영상에 실제 표시된 글자만 인식합니다. 짧게 노출된 표현을 모두 잡는다고 보장할 수 없으며 실제 LoL 영상 OCR 인식률은 미검증입니다.

### 시험 방법
1. 영상 파일을 선택하고 재생하면 ‘재생 중 채팅 감시: 켜짐’ 상태에 검사 수가 표시됩니다.
2. 채팅이 보이는 시점에서 일시 정지한 후 ‘의심 장면 찾기 → 현재 영상 화면 글자 확인’을 눌러 OCR 범위와 텍스트를 확인합니다.
3. 필요하면 왼쪽 넓게/전체 화면으로 바꾸고 다시 확인합니다.
4. 전체 분석 중 부적절한 채팅 후보가 발견되면 완료 전에도 결과 목록에 표시됩니다.

자동 기능의 문법과 문구 분류 규칙은 테스트했지만 실제 LoL 원본 영상의 한국어 채팅 인식률은 측정하지 않았습니다.


## v5.5 영상 채팅 로그 (2026-11-05)

- 로그는 영상 보기와 의심 장면 찾기 양쪽에서 동기화되어 표시합니다.

- **중요:** 이 기능은 인식된 글자를 나열합니다. OCR이 놓친 실제 채팅은 로그에 나타나지 않으며, 화면 내 다른 UI를 채팅으로 오인할 수 있습니다. 실제 게임 영상으로 OCR 정확도 측정을 완료한 상태는 아닙니다.
